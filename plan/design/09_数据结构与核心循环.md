## 三、核心循环：时间戳重放

### 关键原则

**不用每秒 tick。** 所有产出通过「时间戳差值 → 完成行动次数」重放计算。这样：
- 离线与在线走完全相同的代码路径
- 不会因为浏览器后台节流产生误差
- 存档体积小（只存时间戳，不存中间状态）

### 主结算函数

```javascript
/**
 * 结算一个行动槽位从 lastSettle 到 now 的全部产出
 * @returns {SettleResult} 产出、XP、消耗、中断原因
 */
function settleAction(slot, state, lastSettle, now, opts) {
  const { isOffline } = opts;
  const action = ACTIONS[slot.actionId];
  const skill = state.skills[action.skill];

  // ── 1. 计算有效时长 ──
  let elapsedSec = (now - lastSettle) / 1000;

  if (isOffline) {
    const capHours = Math.min(state.base.level + 1, 24);   // 营地离线上限
    elapsedSec = Math.min(elapsedSec, capHours * 3600);     // ★ 超出部分完全丢弃
  }

  // ── 2. 效率系数链 ──
  const modifiers = computeModifiers(action, state, lastSettle, now);
  //  { night: 0.6, rain: 0.8, flowState: 1.1, mastery: 1.25,
  //    proficiency: 1 / proficiencyFactor(Lv), ... }
  //  ★ proficiencyFactor(Lv) = Lv<=25 ? 1+(25-Lv)*2.5% : 1-min((Lv-25)*0.405%,30%)
  //    低等级耗时更长、高等级耗时更短（见 00 第三节）
  const efficiency = Object.values(modifiers).reduce((a, b) => a * b, 1);

  const offlineFactor = isOffline ? 0.6 : 1.0;              // ★ 离线折算
  const actionId = (action.skill === 'hunting' && isOffline) ? 1.0 : offlineFactor;
  //  ↑ 狩猎/陷阱是唯一离线 100% 折算的技能（设计签名）

  // ── 3. 生存消耗预算（按小时推进）──
  const survival = simulateSurvival(state, elapsedSec, isOffline);
  //  返回 { effectiveSec, haltedAtSec, reason, consumed }
  //  水耗尽 → haltedAtSec 提前，reason = 'thirst'

  const billableSec = Math.min(elapsedSec, survival.effectiveSec) * actionId;

  // ── 4. 完成次数 ──
  const baseDuration = action.durationSec / efficiency;
  const completed = Math.floor(billableSec / baseDuration);
  if (completed <= 0) {
    return { completed: 0, halted: survival.reason, ...emptyResult() };
  }

  // ── 5. 失败判定（逐次独立）──
  const failChance = Math.max(0.01, 0.18 * Math.exp(-skill.level / 35) + 0.01);
  //  失败 → 无产出、不扣材料、仍耗时间与体力、只给 20% XP（至少 1 点）
  //  ★ 全 14 技能通用（含制作配方与建造，建造失败同样不扣材料），见 00 第三节
  const failed = countFailures(completed, failChance);
  const succeeded = completed - failed;

  // ── 6. 产出（含背包上限截断，只有成功次数产出）──
  const rawOutput = scaleOutput(action.output, succeeded, state);
  const { accepted, overflow } = clampToInventory(state, rawOutput);

  // ── 7. XP 与升级（可能触发 Lv51+ 闸门）──
  const xpGain = succeeded * action.xp + failed * failureXp(action.xp);
  //  XP 不受耗时/效率修正影响，只由成功/失败次数决定（见 00 第三节）
  const levelUps = applyXp(state.skills[action.skill], xpGain, state.skillBreakthrough);

  return {
    completed, succeeded, failed, xpGain, levelUps,
    output: accepted, overflow,
    consumed: survival.consumed,
    halted: survival.reason,
    billableSec,
    effectiveDuration: baseDuration
  };
}
```

### 生存消耗模拟

```javascript
/**
 * 按小时逐步扣除水与食物，任一耗尽即中断
 * 这是「离线中途停止」的具体实现
 */
function simulateSurvival(state, elapsedSec, isOffline) {
  const hours = elapsedSec / 3600;
  const reduction = Math.min(state.base.level * 0.02, 0.40);   // 营地减免，上限 40%
  const waterPerHour = 4.0 * (1 - reduction);
  const foodPerHour  = 3.0 * (1 - reduction);

  let water = state.player.thirst;
  let food  = state.player.hunger;
  // 离线时可动用的库存（储水容量 + 雨水棚自动补给 + 库存食物）
  let waterReserve = getWaterReserve(state);
  let foodReserve  = getFoodReserve(state);

  let done = 0;
  for (; done < hours; done += 1) {
    // 每小时先补水补食（自动进食/饮水模拟）
    const wNeed = Math.min(waterPerHour, waterReserve);
    water = Math.min(100, water + wNeed);
    waterReserve -= wNeed;

    const fNeed = Math.min(foodPerHour, foodReserve);
    food = Math.min(100, food + fNeed);
    foodReserve -= fNeed;

    water -= waterPerHour;
    food  -= foodPerHour;

    if (water <= 0) {
      return { effectiveSec: done * 3600, haltedAtSec: done * 3600,
               reason: 'thirst', consumed: { water: ..., food: ... } };
    }
    if (food <= 0) {
      return { effectiveSec: done * 3600, haltedAtSec: done * 3600,
               reason: 'hunger', consumed: { ... } };
    }
  }
  return { effectiveSec: elapsedSec, haltedAtSec: null, reason: null, consumed: { ... } };
}
```

**注意循环粒度是「小时」而非「秒」**：24 小时最多 24 次迭代，性能无忧，且与「每小时消耗」的设计口径一致。

### 离线总结算

```javascript
function settleOffline(saveData) {
  const now = Date.now();
  const last = saveData.lastSettleRealTime;

  // ★ 反作弊：检测系统时间回拨
  if (now < last) {
    return { cheated: true, granted: nothing(), reason: 'clock_rollback' };
  }
  const realElapsed = now - last;
  if (realElapsed < 60_000) return null;    // 少于 1 分钟不弹窗

  const results = [];
  for (const slot of saveData.actionQueue) {
    if (slot.paused) continue;
    results.push(settleAction(slot, saveData, last, now, { isOffline: true }));
  }

  // 期间事件：天气、垃圾刷新、随机事件、陷阱自动收获
  const dayEvents = replayDays(saveData, last, now);

  saveData.lastSettleRealTime = now;
  return buildOfflinePopup(results, dayEvents);   // → 上线弹窗数据
}
```

## 四、反作弊与存档安全

### 时钟回拨

```javascript
// 记录基准
lastSettleRealTime   // 上次结算的真实时间戳
monotonicGuard       // 单调递增守卫值

// 每次结算
if (Date.now() < lastSettleRealTime) → 该段不发放收益
if (Date.now() - lastSettleRealTime > 30天) → 按 30 天上限结算（防止改时间刷一年）
```

### 存档完整性

```javascript
const checksum = sha256(JSON.stringify(saveData) + SALT);
// 校验失败 → 提示「存档可能已损坏或被修改」，加载最近备份，不崩溃
```

**不做在线验证。** 策划案第十节「无强制联网：本地存档 + 可选云同步」——单机放置游戏做严格反作弊没有意义，只需要防止「误改时间导致的收益异常」和「存档损坏」。

### 自动备份

保留最近 5 份存档（每日 1 份 + 每次重大操作前 1 份），存于 `localStorage` 独立 key，主存档损坏时可回滚。

## 五、版本迁移

```javascript
const MIGRATIONS = {
  1: (data) => {
    // v1 → v2：新增 masteryTokens 字段
    data.masteryTokens = { wood: 0, metal: 0, cloth: 0, organic: 0, stone: 0, knowledge: 0 };
    data.skillBreakthrough = Object.fromEntries(
      Object.keys(data.skills).map(k => [k, Math.min(data.skills[k].level, 50)])
    );
    data.schemaVersion = 2;
    return data;
  },
  2: (data) => { /* ... */ }
};

function loadSave(raw) {
  let data = JSON.parse(raw);
  while (data.schemaVersion < CURRENT_VERSION) {
    const migrate = MIGRATIONS[data.schemaVersion];
    if (!migrate) throw new Error('无迁移路径: v' + data.schemaVersion);
    data = migrate(data);
  }
  return data;
}
```

**规则**：迁移函数只增不改，永不删除历史迁移步骤。每个迁移必须能处理「字段缺失」和「字段已存在」两种情况（幂等）。
