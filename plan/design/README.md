## 配套计算脚本

`../_calc_balance.py` 是本文档全部数值的推导脚本，`../_calc_out.txt` 是其输出。任何数值调整都应改脚本重跑，不要手改文档表格——文档中所有表格均由脚本输出誊写。

## 三条必须知道的设计红线

1. **游戏时钟 = 现实时钟 1:1**，不是策划案原文的「1 现实分钟 ≈ 1 游戏小时」。后者会让漂流垃圾每天刷新 330 件，垃圾经济直接崩坏。详见 `00_总览与数值基准.md` 第一节。
2. **技能升级不是唯一的进度闸门**。Lv1–50 靠时间，Lv51–99 靠稀有垃圾合成的「专精凭证」。否则全 14 技能会在第 30 天满级，比策划案设定的 2–3 个月叙事弧早两个月。
3. **所有负面状态都有可提前预防的解法**。策划案第十三节明确要求「生存数值别做成惩罚」，因此每个 debuff 在 `04_生存与区域.md` 中都配了明确的建筑或道具解法。

## MVP 范围建议

按策划案第十二节，首版实装：

- 技能 4 项：采集、伐木、生火与烹饪、建造
- 区域 3 个：北沙滩、东礁石区、荆棘带
- 垃圾系统基础版：普通 + 稀有两级，无关键件保底
- 离线结算 + 本地存档
- 界面：左侧技能列表 + 中间行动面板 + 右侧状态栏（三栏，暂不做图鉴）

MVP 的目标是验证「挂机是否好玩」，不验证内容量。科技树、战斗、剧情、成就全部留到第二版。
